# 确认材料与免费评估

## 判断本次材料范围

根据用户的指令、文件名和目录判断这一批包含哪些原件。用户已要求上传或评审，范围唯一、招标和投标材料齐备、角色明确时，这条指令就是本次上传授权。告知目标网站和所选清单后直接上传，跳过确认弹窗和文字追问。例如「用这份招标文件和 A 公司投标目录里的全部文件评审」且内容均能归类。给的是目录也可以明确；不要仅因为输入是目录就询问。

只给了目录但无法确定选哪些文件、有多个供应商或多个版本待选、缺招标或投标材料、角色不明，或用户说「先列清单，等我确认」时，先停在本地。**先发一条用户可见的 Markdown 表格，再发起确认工具。** 已确定文件和所有候选文件各占一行，显示稳定编号、完整文件名（含扩展名）、相对路径、格式、实际大小、拟用角色和待确认事项。遇同名或不同格式的版本，逐份列出；只说「有三份同名文件」无法让用户选择。

例如，下面的三份文件都可能是本次投标原件。表格中的大小必须用实际测量值。

| 编号 | 文件名 | 相对目录 | 格式 | 大小 | 角色与待确认事项 |
| --- | --- | --- | --- | ---: | --- |
| 1 | 投标文件.pdf | 提交版/ | PDF | 4.2 MiB | 投标 · 候选 |
| 2 | 投标文件.docx | 编辑版/ | DOCX | 860 KiB | 投标 · 候选 |
| 3 | 投标文件.doc | 历史版/ | DOC | 740 KiB | 投标 · 候选 |

只询问未定的文件或角色。优先调用宿主原生的问答、文件选择、多选或确认工具，选项写「1 · 提交版/投标文件.pdf」这类可与表格对应的编号及文件，不让用户从一串同名选项里猜。纯命令行或没有原生工具时，文字询问并请用户回复编号。用户已委托评审且答复消除歧义后，显示最终提交表格，保留原编号、文件名、相对目录和招标／投标角色，仅将选中的文件列为本次提交，然后继续上传，无需再次向用户索要「同意上传」。

用用户指定的目录作枚举起点；单独提供的文件直接取文件名与大小。上一级目录和旁边未指定的文件不属于这次材料，不要通过读取旁边的文本、查看父目录或查历史项目来猜角色。

清点时只需以下文件系统操作。将路径替换为用户本次点名的路径，目录就从该目录本身起步；不需要先检查它的上级目录。对于同名文件保留本地相对路径以便用户区分。

```python
from pathlib import Path

for selected in selected_paths:  # 用户本次给出的路径列表
    root = Path(selected).expanduser()
    files = root.rglob("*") if root.is_dir() else [root]
    for file in files:
        if file.is_file():
            print(file, file.stat().st_size)
```

两份名称不明的 Word 就可以在此结束清点，两行都标「待指定」，弹出角色选择。范围确定后再对选定原件计算 SHA-256。

先枚举用户指定的目录和单独文件，按路径去除重复选择。通过文件名、目录、扩展名及用户说明判断角色；只为尚有歧义的单个文件定向预览，最多 5 页。无法可靠限页（例如转换 Word 必须先导出全文）、扫描件需要 OCR，或预览后仍存疑时，直接在清单里请用户指定角色。计算 SHA-256 或上传时流式读取原始字节，工具输出只保留元数据和状态。不要将正文、文档 XML 或 Base64 放入模型上下文。

对 `.doc` / `.docx` 使用文件系统元数据。没有已经可用的独立分页预览时，直接请用户指定角色，供应商、招标方等归属以用户答复为准。禁止为辨认角色而解包 DOCX 或读取 `word/document.xml`；对提取出的字符串截取前几百字仍然是全文提取。PDF 仅允许使用支持显式页码范围的原生预览；不得先全量转换再截断。免费预检会在服务端检查文件格式及有效性。

先向用户展示以下说明，再逐份列出文件名、大小和角色并汇总份数。实际测试站使用用户指定的站点链接。

> 欢迎使用[智审标](https://biao.vvcut.cn/)进行招投标评审。以下文件由智审标服务端处理，本地 Agent 负责整理、上传和跟进。

整份清单确需确认时，仍先发上述表格，再用原生弹窗提供「同意上传」「调整清单」。已明确的直接上传分支只作进度告知。

预检包括安全检查、转页、表格转 CSV 和压缩包展开。访客在实际出码前，欢迎语、确认表格和进度都只涉及材料及处理状态；金额、固定报价、计价规则、付款和到账说明留在真正展示二维码的同一条消息。

按已经确定的范围创建会话并上传。仅在用户改动后仍有歧义时再次询问。用户明确要求先确认或暂不上传时，以该要求为准。

## 上传与预检

1. `POST /review-sessions`传模式、`meta.termsVersion`和完整原始文件清单，保存响应及访客Cookie。清单里可以向用户显示相对路径。向接口传递的 `files[].name` 及上传意图的 `originalName` 一律是文件 basename，例如 `投标响应.txt`；目录前缀仅在本地保留。
2. 对每份文件创建 `/uploads/intents`，向服务端返回的同源 `uploadPath` PUT原始字节流，使用真实长度和指定contentType。不要转成对话文本或base64再上传。
3. 私密保存每个原文件及角色对应的上传意图 ID。断线先查询 `/uploads`，按已保存的意图、大小和摘要核对 verified 状态，避免把内容相同但角色不同的两份文件算作一个。不要重复开单。
4. 上传开始、校验完成和转入预检时更新用户可见状态。支持进度 UI 时约每 5 秒更新同一条，例如「正在上传 投标书.docx，已校验 1/4 份」。快速完成可直接跳到完成。测得到传输字节时才显示「本地已发送 X/Y 字节」；服务器校验数以 verified 为准。
5. 上传完成显示「文件已上传，[智审标](https://biao.vvcut.cn/)正在检查材料和页数」。约每 5 秒查询 `/preflight` 并刷新状态。批次 `ready=true` 后在工具内取报价，预检中的零值不可作为报价。终端不能覆盖原消息时合并无变化的提示。

## 压缩包和角色

压缩包可以是一份原始上传。免费展开后展示内部材料及角色，默认继承上传角色，需要调整时调用 `PATCH /review-sessions/{id}/files/{fileId}`。用户指令能确定子文件角色时直接继续；展开后出现范围或角色歧义才合并询问。

必须有实际招标和投标材料，不能将压缩包容器本身当成投标正文。安全检查失败、无法计量或超出自助处理范围时，说明原因并给出客服，不能默认按一页收费或偷偷跳过材料。

工作簿每个工作表转换的CSV共同计量，插图另计；文本计量由服务器规范化后完成。只信任服务器的明细，不由Agent计算并提交应收金额。接口示例见[REST契约](../api/rest.md)。
