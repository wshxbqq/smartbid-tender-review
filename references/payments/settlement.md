# 固定报价与付款

## 开始前锁定总价

全部材料预检完成后在工具内调用 `POST /review-sessions/{id}/quote`。访客此时只保存报价，等实际二维码可展示再把报价、码和付款说明一并发出。API Key 账户直接进入报价确认。

将预检的文件 ID 与本次报价清单对应，逐份列出文件名和服务端计量值。只对本单实际有费用的类别列算式。文档每页 0.10 元，独立图片和工作簿抽取的插图每张 0.10 元，规范化文本按整批总字节数除以 10240 向上取整，每档 0.10 元。压缩包外壳及文档页内图片不重复收费。明细以服务端去重后的计费量和分项金额为准；发现差异先核对原报价，不自行改价。

到展示时使用服务端的 `quoteMarkdown`。文件清单下的各项算式各占一行加粗标题，再列总价、紧随其下的费用覆盖说明和本地 Token 说明。已有报价缺少样式时按下面的顺序补齐，实际数字取自本单：

招标文件 8 页 + 投标文件 12 页 = 20 页

### **文档费：20 页 × 0.10 元/页 = 2.00 元**

## **本次总价 ¥2.00**

## **总价已包含全部 OCR 和评审费用（含服务端模型 Token）。**

**评审在服务端执行，评审过程不消耗本地 Agent 的 Token。**

随后显示预计耗时。例如另一批有 100 页、3 张图片和 25 KiB 文本，分项合计为 10.00 + 0.30 + 0.30 = 10.60 元。

展示服务器返回的预计评审用时。核对材料角色，保存 `quoteId`、`inputDigest` 和固定总价。报价有效期为15分钟。开单后以该订单的金额及 `expiresAt` 为准。补证、核验用时和模型重试不会改变订单价格。

## 访客付款后开始

新访客报价的 `paymentTiming="before_review"`。先生成并私密保存付款幂等键，再用有效报价调用 `POST /review-sessions/{id}/payments`，请求体仅含 `quoteId` 和 `confirmedInputDigest`。尚未开始评审，此时无需运行编号。将固定总价、明细、预计耗时和本单付款码放在同一条回复。用户扫码付款确认这笔报价。

从本次会话的 `payment.qrPath` 取码，核对订单号、金额及同源链接。首次展示时先按[保存本地付款附件](local-qr.md)落盘并核对文件；再次展示时检查同单附件仍有效。报价下方依次展示以下三项，每项一次：

1. 本单本地 PNG。将 `qrPngBase64` 在工具内解码到本机私密临时目录并读回校验，用原生图片附件或已存在的本地图片路径显示。`qrImageUrl` 仅作下载来源。不能嵌图时提供同一本地文件链接，不要把远程图片地址、Base64、鉴权头或访客密钥放进对话。
2. 文本码和本地「紧凑查看文本码」入口。聊天内用一个顶格、标记为 `text` 的围栏等宽代码块，逐字保留 `terminalQr` 的方块、行末空格和四周空白区，相邻码行用一个 LF 连接。普通 Markdown 的行高由宿主决定；紧凑预览用固定方格显示原字符，即使聊天的字体行距较大也可打开查看。不要再给整个 `paymentMarkdown` 套第二层围栏。
3. 代码块下方的 `[支付宝付款链接](本订单实际的 browserUrl)`。保持链接在代码块外，用户可直接点击。

收款码及付款提示的实付金额以本单付款回执的 `amountCents` 为准。若与材料报价不同，保留原报价算式并将其标为「材料报价」，在二维码旁单独标出「本单实付」，两者都从各自回执读取。

兼容没有 `paymentMarkdown` 或仍返回旧外链图片模板的服务时，忽略旧图片引用，从原单回执保存本地附件并按上述顺序组合。取码失败时重试原单，用户可见提示仅说「二维码暂未准备好，正在重试」。在有效二维码能展示前，报价、付款链接、到账及开审说明留在工具内。

告诉用户「请扫码付款。到账后，[智审标](https://biao.vvcut.cn/)会自动开始评审，我会继续跟进。」先让用户看到码和链接，再进入等待工具调用。用户无须回复「已付款」。只有服务端能确认到账，不能根据用户口述、截图或浏览器跳转自行调用启动接口或本地评审。

付款单有效期为2小时。查询原单仍待付时沿用同一付款码，即使原报价已过15分钟也不另行报价。用户明确放弃时取消原单；过期、支付响应丢失或状态未知时查询原单，以服务端核实的结果为准。只有原单确认关闭，且用户仍要评审时，才重新取得有效报价和付款码；金额或材料变化时应让用户看到新的明细和总价。

到账后可以开下一单；原单报告验证且 `deliveryAvailable=true` 才可交付。报告验证前取消、系统失败或实际执行超时，实付款全额退回原支付账户。退款处理中显示实际状态，服务端确认退款后再告知完成。

## 账户积分与历史订单

API Key 账户在用户确认报价后调用 `/start`，由服务端冻结固定报价，报告验证后结算。余额不足或有欠款时展示固定价、可用余额、欠款、实际缺口及可复制的 Markdown 充值链接，用户充值后继续原项目。仅在用户明确要求时打开浏览器。

恢复上线前已有 `runId` 的旧访客任务，按原账单的 `paymentTiming` 处理。原规则为 `after_quote_confirmation` 的任务在待付款时可以开单；原规则为 `after_verified_report` 的任务在报告验证后开单。两类历史订单沿用原 `billId` 和已有付款记录。尚未启动的访客旧报价按新流程重新获取有效报价，向用户展示当前总价。
