# 接收任务回调

宿主已有公网 HTTPS 接收地址时，可为本次任务登记回调。使用本次会话凭据调用 `PATCH /review-sessions/{id}/callback`，发送 `{"url":"<宿主接收地址>"}`。接收端先处理验证请求：收到 JSON 类型 `callback.challenge` 时，以 HTTP 200 纯文本原样返回其中的 `challenge`。完成登记后将返回的 `signingSecret` 私密保存；发送 `{"url":null}` 可注销。

接收事件时读取 `X-SmartBid-Timestamp`（Unix 秒）和 `X-SmartBid-Signature`。用 UTF-8 密钥计算 HMAC-SHA256，输入为时间戳、一个英文句点和收到的原始请求体字节，签名格式为 `sha256=<小写十六进制>`。先验证时间戳处于最近五分钟，用恒定时间比较签名，再读取事件。根据 `id` 去重并核对 `sessionId` 和 `runId`。每个订阅有独立递增的 `sequence`。保存事件后返回 2xx，重试保持原 ID 和序号。收到跳号或乱序事件时查原会话状态；读取评审日志仍使用日志自己的游标。

回调用于提示阶段变化、进度、收款、交付、退款或后台心跳。收到通知后以鉴权状态接口为准，按已处理的游标补齐事件。无地址时每分钟查一次简报，连续 5 分钟静默时核对原会话；宿主无需为接收回调而开放本地端口。
